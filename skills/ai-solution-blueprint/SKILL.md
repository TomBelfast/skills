# AI Solution Blueprint

## Overview

Turn evidence into a constrained AI app or implementation offer. Do not build a broad product. Build the smallest workflow that proves the buyer will pay.

## Required Inputs

Use evidence from:

- `paid-intent-research`
- `keyword-demand-research`
- `community-pain-mining`
- `competitor-offer-analysis`
- `poland-market-adaptation`

If paid intent is weak, create a validation test instead of a product spec.

## Blueprint

Define:

- buyer and job-to-be-done
- painful workflow before the solution
- minimum input data
- AI processing steps
- output the buyer values
- human review or approval step
- success metric
- demo scenario
- pricing and delivery model
- what not to build in v1

## Decision Rule

If the blueprint cannot name a buyer, a paid pain, a measurable outcome, and a validation test, return to research instead of building.

## Common Mistakes

- Building a feature bundle instead of a paid workflow.
- Ignoring delivery and onboarding.
- Adding AI where deterministic automation is enough.
- Creating subscription pricing before proving setup value.
- Skipping the demo and lead magnet.
